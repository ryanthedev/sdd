# sdd: Subagent-Driven Development

![sdd hero](assets/hero.png)

sdd lets Claude hand a job to another CLI and get a clean answer back.

Count the AI coding CLIs installed on your machine. Odds are you pay for two or three and drive exactly one. Codex sits there, logged in, idle, while its quota window rolls over on a schedule whether you spent a token of it or not. Nothing carries forward. You re-buy that capacity every cycle and leave most of it on the table.

Claude stays the brain. But some jobs another tool just does better, and every one of those is a job Claude isn't spending its own context on: transcribing a video, a second pair of eyes on your diff, painting an image, grinding through a scoped refactor. sdd spins the right CLI up as a child process in your repo, lets it do the one thing, and hands back a tidy `{status, summary, artifacts, raw}`. You keep a clean diff. Claude keeps a clear head.

It's one Claude Code plugin: an MCP server plus a couple of Skills.

> Fun aside: the banner up top was generated by sdd itself, with the `agy` harness's `image` kind.

## What you can actually do with it

- **Five reviewers in one turn.** `codex`, `grok`, `kimi`, `qwen` and `mistral` all emit the same output contract, so you can throw one diff at all five and read their findings side by side. Five vendors, five sets of blind spots, and the blind spots don't line up. That's the ensemble review, and it costs you one turn of wall clock instead of five.
- **Get a second opinion on your code.** Or just pick one. Hand your diff to any of them and an independent verdict plus findings comes back while Claude keeps driving.
- **Transcribe an Instagram reel.** Point the video pipeline at a URL (YouTube, Instagram, TikTok, X) and get back the audio, a transcript, and scene-cut keyframes. Great for "what's actually in this video" without watching it.
- **Generate an image.** Ask `agy`, `codex`, or `grok` for a PNG with `kind: "image"`. That's how the banner above got made. No Midjourney seat needed: with `agy` or `codex` the account you already log into covers it, and `grok` bills the same xAI key its reviews do.
- **Hand off the hard stuff.** Give a gnarly refactor a flagship model and high reasoning effort (`dispatch codex` with `model` + `effort`) and let it churn in the background while you keep working.
- **Check what's left in the tank.** `usage` reports how much of your codex quota you've burned, when the window resets, and what credit you're holding. It costs zero tokens and runs no model: it reads the CLI's own account endpoint. Call it before a big fan-out and you'll know whether you're spending surplus or about to hit a wall. It also shows Gemini dollars spent in the last 24 hours and this month against your budget (`~/.config/sdd/budget.json`) in two independent pools reported on two lines: decision work (default $5/day and $50/month) and video fusion, gemini `vision` (default $15/day and $150/month, set under a nested `vision` block), so a video binge can't eat the decision model's budget; and `usage({recent: N})` lists the last N jobs with their cost and outcome. Every finished job is logged to `~/.local/state/sdd/ledger.jsonl`, including failed and cancelled ones. If you run a Claude usage governor, `usage` also leads with its state (`$USAGE_GOVERNOR_DIR/state.json`, default `~/.claude/usage-governor`): weekly %, 24h use, RUN/STOP.
- **Cheap helper agents.** sdd ships three Claude Code agents: `sdd:gemini-judge` ranks, filters or checks a batch (files, screenshots, videos) with Gemini Decisions; `sdd:video-digest` turns a video into a transcript-plus-visuals digest; `sdd:spend-watch` reports Gemini, Claude-governor and codex spend in one answer. They spend Gemini dollars instead of Claude quota.
- **Fan out.** Kick off a batch at once. Every dispatch runs in parallel and returns a job id right away, so Claude can start three jobs and collect them as they land.

## How it works

Three moves, and the first one never blocks:

1. `dispatch` a prompt to a named adapter. You get a `jobId` back immediately. The harness runs in the background.
2. Check in with `status`, or block on `wait` until it's done.
3. Collect the structured result with `result`.

Nine MCP tools drive the whole thing: `dispatch`, `status`, `result`, `wait`, `cancel`, `list_adapters`, `list_models`, `check_adapter`, and `usage`. Job state lives in memory for the session, so a server restart clears it; what persists is one line per finished job in the spend ledger (`~/.local/state/sdd/ledger.jsonl`), which `usage` reads.

You could background a process from Bash and grep its stdout. What you'd be missing is the backstop: every adapter validates an output-contract marker before it calls a job `done`, so a harness that exits 0 without doing the work gets reported as `failed` instead of quietly passing. A misparsed flag, a swallowed prompt, a model that answered the wrong question. Those show up as failures here. In a shell one-liner they show up as a green checkmark.

One thing that's on you, not the server: writable agent dispatches run in parallel with no server-side locking. Pass `readOnly: true` for reviews (enforced natively on `claude`, `codex`, `agy`, `grok`, and `mistral`), and if two writable jobs would touch the same directory, keeping them apart is the caller's job. sdd serializes nothing.

## Install

It ships in the [rtd marketplace](https://github.com/ryanthedev/rtd-claude-inn). Add that once, then install:

```
/plugin marketplace add ryanthedev/rtd-claude-inn
/plugin install sdd@rtd
```

That wires up the MCP server and auto-discovers the `subagent-driven-development`, `commander` and `video-ingest` skills. `commander` runs a whole task as a multi-agent operation: Claude acts as your proxy, charters 3-5 tracks, staffs them with interactive agents in herdr-core (`hc`), subagents and sdd jobs, then verifies and merges. You'll need `bun >= 1.3.0`. Run `bun install` for the two deps (`@modelcontextprotocol/sdk`, `zod`).

The video pipeline also shells out to three tools that `bun install` doesn't manage. Grab them and run the preflight:

```
brew install yt-dlp
brew install ffmpeg
pip install -U mlx-whisper      # Apple Silicon speech-to-text
brew install uv                 # optional — only for `shazam` (song identification)
echo 'GEMINI_API_KEY=...' >> ~/.config/sdd/.env       # optional — only for `gemini` (AI Studio key); read per job
bun run src/lib/preflight.ts    # tells you what's present, what's missing
```

`uv` is optional and reported separately: preflight lists it under `optional[]` and never fails the gate for it. Everything except the `shazam` step runs without it.

**Instagram is the awkward one.** It rate-limits and often demands a login, unlike YouTube, TikTok, or X. Two things help: pass a logged-in session's cookies file (`dispatch yt-dlp` with `cookies`) — use a burner account, never your primary, and never commit or log that file. And run yt-dlp's nightly channel (`pip install -U --pre "yt-dlp[default]"`), since Instagram breaks the extractor often and nightly ships the fixes first. Pair it with `sleepRequests` to throttle.

## The adapters

Twelve ship today, and the ones that do more than one thing expose the extras as *kinds* on the same name (`agy` has `default`/`image`/`vision`; `codex` and `grok` have `default`/`image`; `gemini` has `default`/`vision`). `list_adapters` shows you which ones are installed (plus supported effort levels and `readOnly`), `list_models` queries live model catalogs and effort tiers (`codex`, `agy`, `grok`, `claude`), `check_adapter` tells you whether one is actually logged in and usable, and `usage` tells you how much quota is left.

| Group | Adapters | For |
|---|---|---|
| Agent harnesses | `claude` | Review, second opinions, implementation via `claude -p --no-session-persistence`. Supports `model`, `effort` (`low..max`), `readOnly`, and `addDir` |
| | `codex` | Review, second opinions, implementation. Pick the tier per call with `model` + `effort` (`low..ultra`) + `serviceTier`; supports `readOnly` and `addDir` |
| | `agy` | Review / implement. Supports `model`, `effort` (`low..max`), `readOnly`, and `addDir` |
| | `grok`, `kimi`, `qwen`, `mistral` | Second opinions from xAI, Moonshot, Alibaba, and Mistral (`readOnly` supported on `grok`/`mistral`; `model` on `grok`/`kimi`) |
| Image + vision | `agy` / `codex` / `grok` + `kind: "image"` | Text to a PNG (agy: Nano Banana; codex: imagegen skill; grok: imagine skill) |
| | `agy` + `kind: "vision"` | Fuse a transcript + keyframes into one understanding JSON |
| | `gemini` + `kind: "vision"` | The same fusion over the Gemini API on Flash-Lite, for when agy is out of quota: same opts, same JSON, about $0.007 for a 2-minute reel |
| Video pipeline | `yt-dlp`, `whisper`, `ffmpeg-frames` | Pull a video, transcribe it, extract scene-cut keyframes |
| | `shazam` | Name the song playing in it, by acoustic fingerprint — the one thing the transcript and the frames both can't tell you |
| Decision model | `gemini` | The decision model. The Gemini Decisions API answers yes/no, choice, and score questions with probabilities over text **or** images, video, audio, and PDFs, in about 1 s at $0.10 per million input tokens. It never writes text. Legacy `state` / `boolean` request fields are accepted |

### What's paying for what

Three of the harnesses ride an account you already log into. Five want an API key. Four are free. Worth knowing which is which before you fan out, because "spend the surplus I already bought" and "meter myself a few cents per review" are different decisions:

| Harness | Auth | What a job costs |
|---|---|---|
| `claude` | Claude Code login flow or `ANTHROPIC_API_KEY` | Plan quota (or API key). |
| `codex` | OpenAI/ChatGPT login flow | Plan quota you've already paid for. `usage` shows what's left and when it resets. |
| `agy` | its own login flow | Account-backed, same shape as codex. No per-token key to fund. |
| `grok`, `kimi`, `qwen`, `mistral` | one env var each (`XAI_API_KEY`, `MOONSHOT_API_KEY`, `DASHSCOPE_API_KEY`, `MISTRAL_API_KEY`) | Metered per token. Cheap for a review, but it's real spend, so fan these out deliberately. |
| `yt-dlp`, `whisper`, `ffmpeg-frames` | none | Free. whisper and ffmpeg run locally on your own silicon. |
| `shazam` | none | Free. Needs `uv` on PATH; it provisions the recognizer on first run and caches it. |
| `gemini` | `GEMINI_API_KEY` (Google AI Studio) | Metered. Decisions: $0.10 per million input tokens, nothing for output; a 19-second clip with four questions is about $0.0002. Vision fallback: Flash-Lite list price, about $0.007 per 2-minute reel. Inputs, including local media files, go to Google. |

Each harness has its own quirks: flag ordering, the marker it emits, what auth it needs. The full per-harness reference (capabilities, auth, and every gotcha) lives in **[`skills/subagent-driven-development/references/harnesses.md`](skills/subagent-driven-development/references/harnesses.md)**. For the orchestration doctrine (when to fan out, when to serialize, how to use `wait`) see **[`skills/subagent-driven-development/SKILL.md`](skills/subagent-driven-development/SKILL.md)**.

## Decision calls without MCP: `src/cli/decide.ts`

Programs that are not MCP clients (a script, or a CLI tool such as [alsp](https://github.com/ryanthedev/agent-lsp)) can make Gemini decision calls through sdd and still get its budget check and spend record:

```
bun run src/cli/decide.ts [--timeout-ms N] [--model M] [--] <request.json> [<results.json>]
```

It runs the same code path as `dispatch` with `adapter: "gemini"` (the default kind): the script refuses when the budget is spent, and one line per job lands in the spend ledger. The request and results JSON are documented in `assets/gemini-decide.ts`; `"dryRun": true` estimates cost and calls nothing. On success stdout is the absolute results path and the exit code is 0. Exit 1 means the job failed (stderr has the script's reason, such as `budget exceeded`; a timeout or SIGTERM also exits 1). Exit 2 is a usage error. See `docs/usage-contract.md` section 3a.

Setup and a minimal call:

- **API key.** `GEMINI_API_KEY` from the environment, or a `GEMINI_API_KEY=` line in `~/.config/sdd/.env` (`$XDG_CONFIG_HOME/sdd/.env` when that is set). The job's own directory `.env` is never read.
- **Budget limits.** Read from the budget file in the same config folder (`~/.config/sdd/`, or `$XDG_CONFIG_HOME/sdd/`); `docs/usage-contract.md` section 4 gives its name and shape. Missing means the defaults: $5/day and $50/month for decision calls. Spend is totalled from the local spend record under `~/.local/state/sdd/`. A per-job cap comes from the request's `maxCostUsd` (default $1).
- **Request.** A JSON file (inline JSON is refused here). Questions are named; each item is answered against every question:

```json
{
  "questions": {
    "is_bug_fix": {"type": "noul", "instructions": "Is this change a bug fix?"}
  },
  "items": [
    {"id": "a", "input": "Fix off-by-one in the page counter"},
    {"id": "b", "input": "Add dark mode toggle"}
  ]
}
```

```
bun run src/cli/decide.ts request.json results.json   # prints the absolute path of results.json
```

Add `"dryRun": true` to the request first to see the estimated cost without calling the API.

## Codex subagents

The plugin ships two Claude Code subagents that hand the heavy lifting to codex through the MCP server, so Claude spends few tokens:

- **`sdd:codex-builder`**: takes a scoped build task, checks codex quota first, dispatches codex, then independently diffs against a baseline, flags any file changed outside the stated scope, and runs the project's tests itself. The diff is left uncommitted for you.
- **`sdd:codex-reviewer`**: a second-opinion review of a diff or files. It checks that codex left the tree unchanged and labels every finding CONFIRMED or UNCONFIRMED after checking it against the code.

Both need a git repo as the target directory (codex refuses non-git dirs). Their definitions live in [`agents/`](agents/).

## Adding an adapter

Drop a file in `src/adapters/` that exports the `Adapter` shape (`name`, `buildArgs`, `injectContract`, `parseResult`, plus optional `binary`/`probeable`). There's no registry to edit. Discovery picks it up, skips anything malformed with a warning instead of crashing, and ignores infra files (`_`-prefixed helpers, tests, `discover.ts`/`types.ts`). See the harness reference and any existing adapter for the pattern.
